**ZipHere** — крошечная утилита для Windows, которая берёт на себя распаковку ZIP-архивов:

- **автоматически распаковывает** каждый новый ZIP, который вы скачали в «Загрузки»;
- добавляет в меню правой кнопки на любом ZIP-архиве пункт **«Распаковать здесь»**;
- после успешной распаковки **убирает архив в корзину**.

Никаких Python, .NET SDK, архиваторов и прочего: установщик — один `.exe` файл, а собирается он встроенным в Windows компилятором.

```
Скачали archive.zip  →  через пару секунд рядом папка archive\, а сам архив в корзине
```

## Возможности

- **Автораспаковка загрузок.** Фоновая программа со значком в трее следит за папкой «Загрузки». Как только браузер докачал новый `.zip`, он распаковывается, и вы получаете уведомление.
- **Автозапуск.** Устанавливается один раз и стартует вместе с Windows, открывать ничего не нужно.
- **«Распаковать здесь»** в меню правой кнопки для ZIP-файлов в любой другой папке.
- **Архив — в корзину.** После успешной распаковки исходный ZIP перемещается в корзину и при необходимости восстанавливается оттуда.
- **Безопасно для ваших файлов.** Ничего не перезаписывается: если папка уже существует, создаётся `имя_1`, `имя_2` и т. д. Если архив повреждён или защищён паролем, он остаётся на месте, а недоделанная папка убирается.
- **Управление из трея.** Автораспаковку можно в любой момент выключить и включить.
- **Без прав администратора** — всё пишется только в профиль текущего пользователя (`HKCU` и `%LOCALAPPDATA%`).
- **Без зависимостей** — работает на чистой Windows 10/11 (используется .NET Framework 4, который уже встроен в систему).
- **Один файл** — `ZipHereSetup.exe` устанавливает, обновляет и удаляет программу.

## Установка

1. Откройте страницу [**Releases**](https://github.com/INTROLMMORTAL/Zip-Here/releases) и скачайте `ZipHereSetup.exe`.
2. Запустите его, прочитайте описание и нажмите **«Да»**.
3. Готово: значок ZipHere появится возле часов, и программа будет запускаться вместе с Windows.

> Хотите убедиться, что файл не подменён? Рядом с релизом лежит `ZipHereSetup.exe.sha256`. Проверка в PowerShell:
> ```powershell
> (Get-FileHash .\ZipHereSetup.exe -Algorithm SHA256).Hash.ToLower()
> ```
> Результат должен совпасть с содержимым `.sha256`-файла.

Либо [соберите `.exe` сами](#сборка-из-исходников) — это два клика.

**Обновление.** Запустите новый `ZipHereSetup.exe` ещё раз и выберите «Да — обновить».

## Использование

### Автоматически

Просто скачивайте ZIP-файлы. Как только загрузка завершится, рядом появится папка с распакованным содержимым, а архив уйдёт в корзину. Над значком в трее всплывёт уведомление с результатом.

Значок в трее (в Windows 11 он может прятаться под стрелкой `^` рядом с часами):

| Пункт меню | Действие |
|---|---|
| **Автораспаковка загрузок** (галочка) | включить или выключить автоматическую распаковку |
| **Открыть папку загрузок** | открыть «Загрузки» в Проводнике (то же — двойной клик по значку) |
| **Выход** | закрыть программу до следующего входа в Windows |

Выключение автораспаковки запоминается и сохраняется между перезапусками.

### Вручную

Правая кнопка мыши по любому `.zip` в любой папке → **«Распаковать здесь»**. Содержимое окажется в папке с именем архива рядом с ним, а архив уйдёт в корзину.

**Windows 11.** В новом коротком контекстном меню пункта нет — он находится в **«Показать дополнительные параметры»** (или нажмите `Shift + F10` по выделенному архиву). Это ограничение самой Windows для классических пунктов меню.

Примеры:

| Было | Стало |
|---|---|
| `Downloads\files.zip` | `Downloads\files\…`, архив в корзине |
| `Downloads\files.zip` (папка `files` уже есть) | `Downloads\files_1\…`, архив в корзине |

## Что происходит с архивами

Раз программа сама удаляет файлы, вот её правила в одном месте:

- Следит **только за папкой «Загрузки»** текущего пользователя и **только за новыми файлами**: ZIP, которые лежали там до запуска, не трогаются.
- Дожидается, пока файл докачается: он должен открываться и перестать расти.
- Архив отправляется **в корзину**, а не удаляется навсегда. Его можно восстановить.
- Если распаковка не удалась (повреждён, с паролем, не хватило места), архив **не удаляется**, незаконченная папка убирается, а в трее появляется уведомление об ошибке.
- Если вам нужно сохранить конкретный ZIP (например, чтобы переслать его), выключите автораспаковку в меню значка или достаньте архив из корзины.

## Удаление

**Штатно:** снова запустите `ZipHereSetup.exe` и выберите «Нет — удалить». Будут убраны пункт меню, автозапуск, настройки и файлы программы.

**Вручную** (если установщика под рукой нет), в `cmd`:

```bat
taskkill /f /im ZipHere.exe
reg delete "HKCU\Software\Classes\SystemFileAssociations\.zip\shell\ZipHere" /f
reg delete "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v ZipHere /f
reg delete "HKCU\Software\ZipHere" /f
rmdir /s /q "%LOCALAPPDATA%\ZipHere"
```

## Сборка из исходников

Требуется только Windows: компилятор `csc.exe` входит в состав .NET Framework 4, который есть в любой Windows 10/11.

```bat
git clone https://github.com/INTROLMMORTAL/Zip-Here.git
cd Zip-Here
build.bat
```

Результат — `dist\ZipHereSetup.exe`.

Тот же вызов компилятора без скрипта:

```bat
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /optimize+ /codepage:65001 ^
  /out:dist\ZipHereSetup.exe ^
  /r:System.dll /r:System.Drawing.dll /r:System.Windows.Forms.dll ^
  /r:System.IO.Compression.dll /r:System.IO.Compression.FileSystem.dll ^
  /r:Microsoft.VisualBasic.dll ^
  src\Installer.cs
```

`build.bat` принимает необязательный аргумент `nopause` — он отключает паузу в конце (используется в CI).

## Как это работает

Весь код — один файл [`src/Installer.cs`](src/Installer.cs). Программа работает в трёх режимах в зависимости от аргументов запуска:

| Запуск | Что происходит |
|---|---|
| Без аргументов | Установщик: предлагает установить; если уже установлено — обновить или удалить |
| `--watch` | Фоновый режим: значок в трее и слежение за «Загрузками». Запускается автозапуском Windows; второй экземпляр не стартует (проверка через `Mutex`) |
| `путь\к\архиву.zip` | Ручная распаковка из меню правой кнопки: окно с индикатором, затем архив уходит в корзину |

### Установка

1. Останавливает уже запущенные копии (`ZipHere.exe`), чтобы можно было обновить файл.
2. Копирует свой `.exe` в `%LOCALAPPDATA%\ZipHere\ZipHere.exe`.
3. Прописывает в реестре (всё в `HKCU`, права администратора не нужны):

```
HKCU\Software\Classes\SystemFileAssociations\.zip\shell\ZipHere
    (по умолчанию) = "Распаковать здесь"
    Icon           = "zipfldr.dll"
    \command
        (по умолчанию) = "…\ZipHere\ZipHere.exe" "%1"

HKCU\Software\Microsoft\Windows\CurrentVersion\Run
    ZipHere = "…\ZipHere\ZipHere.exe" --watch

HKCU\Software\ZipHere
    AutoUnpack = 1        (создаётся при первом переключении галочки в трее)
```

4. Сразу запускает фоновый режим, перезагрузка не нужна.

Ветка `SystemFileAssociations\.zip` добавляет пункт к любым `.zip`, независимо от того, какая программа назначена для них по умолчанию. Значок пункта берётся из системной библиотеки `zipfldr.dll`.

### Автораспаковка

Класс `TrayApp` создаёт `FileSystemWatcher` на папку «Загрузки» (путь запрашивается у системы через `SHGetKnownFolderPath`, поэтому работает и с перенесённой папкой). Браузеры качают во временный файл (`.crdownload`, `.part`) и в конце переименовывают его в `.zip`, поэтому обрабатываются события создания и переименования. Для каждого файла в пуле потоков:

1. ждёт, пока файл можно открыть монопольно и размер перестанет меняться (не больше 15 минут);
2. вызывает `Unpack`;
3. показывает уведомление с результатом.

### Распаковка

`Unpack` определяет целевую папку (`<папка архива>\<имя архива>`), подбирает свободное имя (`_1`, `_2`, …) и вызывает `ZipFile.ExtractToDirectory`. При успехе исходный файл отправляется в корзину через `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile` с `RecycleOption.SendToRecycleBin`; при ошибке созданная папка удаляется, а архив остаётся нетронутым. Защиту от Zip Slip (выход за пределы целевой папки через `..\`) обеспечивает сам .NET Framework 4.6.2+; в более старых версиях полагайтесь на то, что архивы приходят из доверенных источников.

### Почему C# и `csc.exe`

Задача — «ничего не устанавливать». `csc.exe` присутствует в каждой Windows начиная с 7, поэтому проект собирается без Visual Studio, SDK и сторонних пакетов. Код намеренно написан на C# 5, чтобы компилироваться этим встроенным компилятором.

## FAQ и ограничения

**Как выключить автораспаковку, но оставить пункт в меню?**
Значок в трее → снять галочку «Автораспаковка загрузок».

**Значка в трее нет.**
В Windows 11 новые значки прячутся под стрелкой `^` рядом с часами; перетащите значок на панель, чтобы он был всегда на виду. Если там пусто, запустите `ZipHereSetup.exe` и выберите «Да — обновить»: фоновая программа запустится заново.

**Распаковалось не всё / архив остался на месте.**
Значит, распаковка не удалась. В трее показывается причина. Частые случаи: архив повреждён, защищён паролем или на диске нет места.

**Файл скачался не в «Загрузки».**
Автоматически обрабатывается только папка «Загрузки». Для остальных мест есть «Распаковать здесь» в меню правой кнопки.

**Антивирус или SmartScreen ругается на файл.**
Файл не подписан цифровой подписью (она платная), поэтому SmartScreen может показать предупреждение «Windows защитила ваш компьютер» — нажмите «Подробнее» → «Выполнить в любом случае». Программа меняет разделы реестра, копирует свой `.exe` и добавляет автозапуск, что иногда срабатывает на эвристики антивирусов. Исходники открыты, а `.exe` можно собрать самостоятельно.

**Поддерживаются только `.zip`?**
Да. `.rar`, `.7z`, `.tar.gz` не поддерживаются.

**Архивы с паролем?**
Не поддерживаются: будет показана ошибка, архив останется на месте.

**Кракозябры в именах файлов.**
Если архив создан старой программой, не использующей UTF-8 для имён, кириллица внутри может отобразиться некорректно: .NET Framework использует системную кодовую страницу.

**Пункт не появился в меню правой кнопки.**
Проверьте, что смотрите именно ZIP-файл, а в Windows 11 откройте «Показать дополнительные параметры». Если не помогло — перезапустите Проводник (Диспетчер задач → Проводник → Перезапустить).

**Можно ли установить для всех пользователей?**
Сейчас нет: установка идёт в профиль текущего пользователя, чтобы не требовать прав администратора.

## Релизы и CI

Workflow [`build.yml`](.github/workflows/build.yml) запускается на `windows-latest`:

- при каждом push в `main` и pull request — собирает `ZipHereSetup.exe` и прикладывает его как артефакт запуска;
- при пуше тега вида `v1.1.0` — дополнительно создаёт GitHub Release с `ZipHereSetup.exe`, файлом контрольной суммы и автоматически сгенерированным списком изменений.

Выпуск новой версии:

1. Обновите версию в `src/Installer.cs` (`AssemblyVersion` и `AssemblyFileVersion`) и добавьте запись в `CHANGELOG.md`.
2. Создайте релиз на GitHub: **Releases → Create a new release**, тег вида `v1.1.0` (**Create new tag on publish**). Сборка запустится сама и приложит `.exe`.

## Участие в разработке

Issues и pull request'ы приветствуются. Пожалуйста, учитывайте принципы проекта:

- **минимализм** — только распаковка ZIP, никаких настроек «на вырост»;
- **ноль внешних зависимостей** — сборка должна работать на чистой Windows одним `build.bat`;
- **совместимость с C# 5** — без интерполяции строк, `?.`, `nameof` и т. п., иначе встроенный компилятор не справится;
- **осторожность с файлами пользователя** — ничего не перезаписывать и не удалять безвозвратно.

Идеи, которые подходят проекту: выбор папки для слежения, многоязычный интерфейс (по языку системы), подпись исполняемого файла, установка для всех пользователей, значок в `.exe`.
